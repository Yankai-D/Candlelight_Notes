# 长期使用、叙述模板与质量证据

作者持续使用带来的问题、反馈与设计调整，是本项目已有的产品验证。不能因为尚未开展独立评测，就把这些经验描述成“没有测试”。也不能由同一位作者的使用满意，推断所有学习者或所有论文上的教学效果。

本轮保留论文讲述模板作为核心资产，不改变生产提示或默认样稿，不额外调用模型。新增的是把反馈、模板版本、回归和生成记录连起来的证据链。

## 需要保护的讲述特征

- 问题先建立语境，概念、符号和推导回应这个问题，局部计算完成后回到方法意义。
- 关键转折充分展开，已知代数与重复铺垫收紧；不把每个概念变成等长栏目。
- 背景、直觉和原理融合为连贯正文，避免译文后追加三块说明。
- 用户画像只改变前置知识的解释深度，叙述视角、术语、准确性和基本文风稳定。
- 补充解释有来源边界；流畅不能通过省略条件、擅加机制或保证来实现。
- 纸条和局部协作沿用正文风格，同时遵守用户指定的编辑范围。

实现资产为 `shared/editorial-policy.mjs`、`shared/writing-templates.mjs` 和 `shared/course-default-sample.json`。论文长文与结构化讲义继续分开。它们是可维护的产品资产，护城河仍需通过持续使用中的质量、故障修复与可重复的生成来积累；本项目不声称提示文本本身不可复制。

## 已有证据与本轮新增证据

[长期使用记录](../evals/notes/long-use-evidence.json) 保留用户原话、对应要求、代码测试入口和未覆盖边界。日期是整理日期；不虚构每条反馈的发生日期、使用小时数、用户数或故障率。

[ResNet A/B 反馈](../evals/notes/runs/2026-10-18-evidence/user-feedback.json) 已有具体段落定位：用户偏好 A 对“更深模型原则上不该更差”和实际退化之间冲突的展开。它是开发与风格选择证据，没有被转换成数字教学分数，也没有外推到全部材料。

现有 [校准材料](../evals/notes/calibration/README.md) 中的数学用途、画像文风、重复铺垫与纸条反例继续使用。它们已经参与开发，不重新包装成未见测试集。

`node scripts/snapshot-product-evidence.mjs` 检查上述引用是否存在，生成本次源码、模板及相关用例的哈希快照。完整工程门禁会执行这个步骤。它只证明证据可定位，不能自动裁定文字好不好。

应用中的“修改记录 → 查看生成来源与调用记录”保留请求前的目标、画像、模板/样稿、来源上下文、模型、实际请求次数、格式修复事件与供应商返回的 token 用量。未返回用量时不猜测。记录不含连接凭据，但含学习内容，应视为私人资料。旧生成不补造记录；格式校验通过不表示已写入笔记或事实已获人工审定。

## 下一次模板变更如何验收

1. 用实际阅读中遇到的段落说明问题，保留当前笔记、原文定位和生成记录。先描述“哪一处难读、为什么”，不先给总分。
2. 冻结当前模板，明确这次改动应改善的特征及必须保留的特征；避免同时更换模型、模板和材料。
3. 跑已有机械回归。采用相同输入与预算生成候选前，另行确认真实 API 开销；这轮没有启动新实验。
4. 审阅完整上下文中的两个候选，记录更偏好的版本、具体句段、原因以及事实或条件错误。匿名标签只隐藏方案身份，不把项目作者审阅称为独立审阅。
5. 接受变更时保存新模板与样稿快照，原版和反例留下；不能以总分提高掩盖某个关键条件缺失。

需要独立教学结论时，另招审阅者、另选未参与调教的材料，并观察学习任务表现。那是后续研究范围，不妨碍当前以长期使用驱动软件改进。

## 长期使用回归的边界

`tests/browser/workspace-maintenance.mjs` 加速执行 16 次真实编辑/保存/往返操作及 4 次刷新，并验证恢复空间、原文关联和冲突另存。两次堆内存采样只留作诊断，不用来宣布无内存泄漏或替代数小时使用。作者的长期使用和这组加速回归分别记录，互相补充。
