## 结论与证据边界

| ND-03 | P3 | 检查脚本在最终源码指纹复核前打印“全部通过”；旧候选实际退出失败且报告正确，但终端文案误导。现在只在最终报告确认通过后打印成功。 |

ND-02 的修复前失败证据保存于 `artifacts/discovery-delete-before.log`。定向回归为 21 项通过。首轮完整 check 的 13 个执行阶段通过，但期间加入 ND-01 后源码指纹改变，报告正确标记失败；旧包与报告均保留，未作为最终交付依据。修复后重新固定源码、重新执行完整检查和打包。

附加原生识别验收首次把素材 ID 当成带 `paper-` 前缀的笔记 ID，导致夹具定位失败；原生阅读、保存、重启已通过。改为按本次写入的唯一测试标记定位实际索引记录，再对同一份安装包重跑，失败记录仍保留于 `native-final/failure.log`。该调整没有改变产品代码或安装包字节。

最终源码检查：325/325 测试、8/8 浏览器流程、13/13 阶段通过，约 300 秒，前后源码指纹一致。完整回归仍会输出 React act、PDF.js wasm 回退及较大前端分块提示；未通过隐藏提示取得通过结果。

独立空目录按当前锁文件执行 `npm ci --no-audit --no-fund`，安装 445 个包。仅设置 `ELECTRON_SKIP_BINARY_DOWNLOAD=1`，没有关闭其余安装脚本；Electron 二进制由锁定版本的最终打包程序验收。本轮完整 check 在已核对的工作区运行，不能把这项依赖安装称为“另一台干净电脑上完整验收”。

200 份合成笔记（约 3.72 MB）的本机文件库负载检查：扫描 657 ms、关联 638 ms、第一次列表读取连同自动扫描 861 ms，预览 JSON 约 52.6 KB。过程内最高 RSS 约 125 MiB，包含测试进程及解析开销。此样例只验证一般批量识别可完成；未代表 1000 份大型笔记、网络共享盘、低配电脑或 UI 首屏性能。

扫描有目录项／深度／数量／单文件体积上限，拒绝链接和配置／安装目录；确认前重新核对实际文件。列表仍一次读取全部笔记，较大资料库的端到端性能尚缺系统基准。此限制不能由“扫描已限额”掩盖。

## Harness 评估

生产系统已形成可执行契约：学习目标、稳定画像、风格模板和原文分别进入上下文；模板快照固定同一笔记的风格；纯翻译不使用画像。生成和编辑返回统一内容节点，校验修改范围、修订号及来源定位后提交。整篇生成按章节保存进度；联合资料包有来源范围快照；理想树有阶段检查点、一次有界内容修复和明确重建版本。截断与格式修复有边界，取消不会提交迟到结果。

这些能力可以作为求职项目中已验证的工程成果，但还不足以证明教学质量的护城河。格式正确、引文存在、先修图无环，都不能证明推理忠实、先修充分、难度合适或成本更优。既有真实对照保留了证据强度升级、背景条件缺失等失败；未达要求的提示后缀和数学复核实验仍隔离于生产路径。本轮只重放这些记录，真实模型调用为 0。

后续质量工作的最小闭环是：冻结论文／课件／追问三个任务和材料；补齐独立盲评；同模型同预算比较直接调用、生产 harness 及单项消融；记录可靠性、语义问题、学习可读性、耗时及实际 token 成本；用未参与调参的材料复验。先针对一个有证据的失败类别改善，不用新的自评提示代替测量。
