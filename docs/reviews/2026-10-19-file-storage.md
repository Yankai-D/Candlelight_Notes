# 资料文件存储与卸载策略

## 本轮约定

- 首次保存位置取系统 Documents 已知目录下的“烛光笔记”，不硬编码用户目录，不放在安装目录或 Setup 所在目录。
- 每次导入（本地文件、理想树来源）和创建独立笔记前确认位置。成功保存后记忆选择；取消、失败不修改默认位置。设置更改只影响未来文件。
- 原文副本与完整笔记各自写入选定目录的独立资料文件夹，保留原来的外部文件。内置统计 PDF 从程序资源读取，用户笔记仍独立保存。
- 应用配置区只保留索引、画像、模板和偏好；理想树及下载文件迁入资料目录。卸载保留用户文件与轻量记录，清除 Key、临时 Key、缓存和日志。升级保留 Key。
- 文件缺失时显示路径，允许仅删除记录，绝不以自动保存重新创建丢失文件。正常移除资料会删除管理的副本和笔记，外部原文件不受影响。

## 实现边界

`server/file-library.mjs` 统一管理浏览器开发环境和桌面环境的文件存储。桌面仍使用隔离的 AppData，开发使用项目 `.local-storage`；二者不互相复制 Key 或画像。HTTP 操作使用既有 loopback、Origin、Host 与会话 token 检查。目录不能位于程序、配置或内置资源内；规范化路径并检查 junction，文件名由内部 ID 生成，删除只触及记录中的受管文件。

写入通过同目录临时文件和 rename 提交；同进程请求串行，模板更新保留 revision 校验。路径索引写入后才返回导入成功。目录更改不会搬移现有资料；需要整体迁移时应另行提供有验证与恢复的工作流。

旧 IndexedDB 迁移逐份写入、回读验证，收齐回执并保存偏好后，在事务中核对旧记录未改变再删除旧副本。迁移回执支持中断重试，不能覆盖迁移之后的新编辑。学习树逐文件校验迁移，冲突保留源文件。仅迁移完成后标记允许卸载清理旧 browser 数据；没有完成迁移的旧库暂时保留，优先避免数据丢失，但 Key 仍强制清除。

## 验收

- `tests/file-library.test.mjs`：目录记忆、索引体量、迁移重试、外部删除、禁止自动重建、受管文件删除边界、junction、内置资源、模板 CAS、学习树迁移冲突。
- `tests/file-storage-api.test.mjs`：本机会话鉴权、来源检查、原文字节、非法路径/偏好、模型设置隔离。
- `tests/browser/file-storage.mjs`：从旧库迁移到文件、清除旧 blobs、导入路径确认和记忆、取消不保存、更改设置、重启恢复、缺失文件记录清理；不调用模型。
- `scripts/test-uninstall-policy.mjs`：编译执行生产 NSIS 清理宏，仅指向一次性临时目录，验证升级与卸载的区别、Key/临时 Key 必删、缓存清理、资料/笔记/轻量索引保留及重复执行。
- 原生桌面验收和跨版本迁移仍由 `scripts/test-desktop.mjs` 执行。完整安装器注册、快捷方式和卸载流程须在空白 Windows 用户或虚拟机运行；宏测试不能冒充整个安装器测试。

本轮所有测试只使用隔离的合成资料；不清除自用配置，不调用付费模型，不发布 GitHub。
