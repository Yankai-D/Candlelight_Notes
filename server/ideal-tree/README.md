# 理想学习树：当前实现与边界

理想学习树是学习树界面的独立功能。输入目标后，在后台构建知识、阅读、实践和情境经验节点；节点正文通过项目既有 Markdown/数学编译器显示。当前版本面向本机、单服务进程，不声称已经完成多租户生产部署或大规模学习效果验证。

## 组件与职责

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| `shared/ideal-tree.mjs` | 输入、阶段结果与引用协议；范围、覆盖、依赖和来源引文校验 | 判断一个学习目标是否在教育意义上完成 |
| `prompts.mjs` | 目标、骨架、分支、资料选择、审查和节点论文查找等阶段契约 | 正式数据提交、工具权限、用户画像更新 |
| `research.mjs` | 公开资料检索、受控读取、相关正文窗口、内容快照 | 把题名或模型记忆当作核实正文 |
| `arxiv.mjs` / `node-papers.mjs` | arXiv 官方元数据查找、节点匹配、按需 PDF 下载 | 重建学习路径、将检索结果直接当作适合学习的资料 |
| `runner.mjs` | 持久任务、先修调度、分阶段提交、局部修复、中断恢复 | 让 agent 任意改写其他分支或原有笔记 |
| `adapter.mjs` | 通过现有 `/api/edit` 认证入口分发后台任务命令 | 把用户 Key 写入任务文件 |
| `IdealTree.tsx` | 目标入口、树的逐层展开、节点纸条、来源、导入与构建记录 | 模型生成坐标或界面布局 |

## 运行与保存

`create` 使用请求 UUID 去重，先保存目标，再启动后台工作。请求返回后任务不依赖浏览器连接。阶段为：

1. 目标约定：保存明确要求、范围边界、假设及规模上限。
2. 领域调研与骨架：读取参考资料，构造覆盖全部约定目标的无环分支先修结构。
3. 按先修顺序展开：上下文包含已接受的前置分支，不编造尚未完成的工作。每个分支原子提交。
4. 资料研究：本地页面摘录与检索候选 → 实际读取 → 有引文依据的匹配。没有合适资料时可用第二条查询补查一次，仍不足则保留缺口。
5. 学习路径审查：只检查目标、先修、内容和实践设计，不接收来源可访问性或检索缺口。资料适配由 research 阶段根据实际摘录判断。重要设计问题最多触发一轮相关分支修复，再复核；剩余意见保留供确认。

每阶段结构校验失败只修复一次。临时网络、超时、限流和部分服务端错误只重试一次，认证或权限错误不自动重试；每次尝试和失败原因写入事件。资料匹配仍格式异常时逐阅读节点保留有效结果，其余记为资料缺口，不中断已构建的学习路径。每次启动有独立模型调用预算，单次模型请求有超时。当前一次只运行一个构建。

资料缺口与内容审查独立保存。路径构建完成后，资料尚未匹配不使整棵树进入失败状态。「补充阅读资料」先保留快照，再补查有缺口的阅读任务，不重写节点、不重跑已完成的内容审查、不重置内容修复预算。补查先生成一次新的来源计划，再实际访问候选；仍无适合材料就明确保留缺口。

2026-10-18.1 明确区分构建完成、资料补查和用户重建。完成统一保存为 `complete`；旧 `review` 记录读取时显示为已完成，原审查意见保留。自动内容修订仍最多一轮，结束后不再因残留意见自行调用模型。完成只表示本轮执行结束，不表示所有内容已被证明正确。

`rebuild` 必须包含原树 ID/修订号、请求 UUID、用户的调整建议和理由，用户可明确选择参考旧审查意见。服务端重新读取原树，检查已完成、版本未变化和无其他活动任务，再创建独立 ID 的新版本。稳定画像和原始目标沿用原版本快照；建议和理由进入目标约定、骨架、分支与最终审查。旧骨架仅作参考，不复制旧来源为新内容背书。新版本独立调研、查证与审查，有自己的预算和检查点；失败、取消、断线重试均不覆盖原树。相同请求 UUID 只能返回同一个版本，内容不同则拒绝复用。新版本在构建记录中保留重建依据和返回原版本的入口。

已完成的旧树点击补充资料只补来源；即使中途中断、服务重启，也不会顺带清理正文或重新审查内容。仅在继续未完成的 2026-10-17.1–3 任务时，仍兼容原有定向清理流程：先保留快照，只修订指定节点文案和研究任务，逐节点保存进度；不增删节点或改父子关系。2026-10-17.4 的未完成任务保留已接受检查点继续执行。

任务存放在 `.local-ideal-trees/`（可用 `READING_TREE_IDEAL_DIR` 指定目录），包含目标、稳定画像快照、本地资料摘录、阶段结果和来源证据。Key 只在执行闭包里。保存使用同目录临时文件和原子替换；读取与写入串行，避免 Windows 文件句柄冲突。重启发现未完成任务后标为暂停，不自动重新计费。浏览器关闭不会中止后台任务。只有明确列入兼容列表的旧版可在继续构建时升级。

`rebuild/pause/resume/get/list/export/resource/papers` 均通过同一协议分发。公开导出不包含来源全文、资产路径或 Key；本机内部记录保留引用核对所需的文本。JSON 导出是树与构建记录，原有笔记 PDF 导出流程独立。

## 系统性的检查边界

`learningPathReport` 使用已接受的内容重新验证全树，生成每个目标对应的分支、任务、预期能力以及实践成果/反馈，输出一种满足先修关系的分支顺序。漏目标、非法引用、先修循环和缺失的实践成果/反馈会阻止本轮完成。报告随树保存、导出，在构建记录中可定位到具体节点；没有分数，也不把编号覆盖当成知识真正覆盖。

最终内容审查同时接收原始目标、稳定画像、目标约定、对应关系和分支内容，检查目标转换是否漏项、隐含先修是否超出已声明基础、学习活动能否产出要求的能力、实践或概念理解如何验收。资料是否能访问和推荐证据是否真实仍由独立研究流程处理，不混入内容修复。

当前能提供的是结构约束、可追溯依据和有边界的模型审查，不能保证领域语义完整或教学有效。要证明这方面的质量，仍需要固定领域目标、可靠课程/能力要求作参照、人工标注缺失先修与覆盖问题，并比较同模型同预算下的结果；不能用同一模型自评替代独立验证。跨分支节点级先修目前仍不支持，分支级先修可能过粗。

## 资料研究的真实能力

默认连接 [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api) 搜索学术元数据与可取得的摘要，以及 [MediaWiki REST API](https://www.mediawiki.org/wiki/API:REST_API/Get_started) 获取背景资料。agent 可提出官方课程、文档和论文的 HTTPS 候选地址，工具读取后才允许作为正文来源。它目前不具备通用搜索引擎的全网召回能力。

来源级别分别为：`metadata`（不能选作已核实材料）、`abstract`、`body`、`local`（本机有限页摘录）。PDF 读取抽样页面，长网页抽取与查询相关的正文窗口；具体读取范围保存在 `extent`。链接可访问、文本存在和内容确实支撑学习目标，是不同检查。

资料工具从真实文本提取带编号的连续摘录。模型选择来源和摘录编号，harness 恢复实际原文并再次校验，避免模型抄写引文引起格式修复。兼容旧版逐字引文，但不存在的来源/摘录或伪造引文不会通过。research 阶段评估匹配含义，不能保证语义正确。已取得正文资产的资料可直接导入；已核实的 arXiv 摘要可按需下载 PDF，只有取得真实 PDF 才交给资料库。导入保留来源链接，并将用户当前选择节点的学习要求传入现有学习笔记目标。

读取工具限制 HTTPS、公开地址、响应体大小、时间与跳转次数；HTTP 与 HTML meta refresh 跳转都会重新检查地址，检测循环，并将连接固定到已核验 DNS 地址。网页脚本不执行。构建时直接读取 arXiv 摘要地址会优先尝试 PDF 正文；失败时只保留明确标识的摘要。资产以内容摘要命名，避免同 URL 的新内容覆盖旧快照。检索失败不作为永久缓存。

## 知识节点到论文导入

知识与能力节点显示其直接子阅读任务、明确依赖的阅读任务及以它为先修的阅读任务来源，保留关联任务名称和原推荐理由，不把整条分支的资料自动分配给所有节点。同一 arXiv 论文的不同版本在资料入口和本机导入映射中去重。

点击「查找 arXiv 论文」启动独立 `papers` 任务，结果按树、分支和节点持久化：

1. `paper-plan` 将当前节点目标、正文、稳定画像转为短英文检索词及最多两个已知编号；模型记忆仅是候选。
2. 工具通过 [arXiv 官方 Atom API](https://info.arxiv.org/help/api/user-manual.html) 查询编号与关键词，解析题名、作者和真实摘要。元数据接口异常时，已知编号可回退到官方摘要页，并核对页面编号。
3. `paper-select` 依据实际摘要匹配最多两篇论文，首篇适合开始阅读。必须引用工具生成的摘录编号，不能使用不存在的论文或伪造引文。不合适时允许空结果。
4. 用户点击「下载 PDF 并导入」，工具读取对应官方 PDF、检查实际文件格式和论文编号，然后进入原有导入流程。摘要始终标为摘要，不冒充已读全文。失败不会创建假资料或空笔记。

正常两次模型调用，共享一次格式修正额度，整项任务限时四分钟；无自动无限重试。进度可以轮询、暂停，浏览器关闭后继续；服务重启后明确显示中断。重复点击正在进行/已完成的任务不会再次计费，明确重新查找才更新。失败或空结果保留已有推荐。任务不调用课程构建、审查或修复，不改节点正文、先修关系、用户目标和画像；为避免覆盖保存，目前不与整树构建并行。

API 请求遵循[官方速率限制](https://info.arxiv.org/help/api/tou.html)：单连接，至少三秒间隔；成功查询缓存一天。PDF 作为当前本机应用的个人学习资料保存，不构成公开论文镜像服务。

## 验证与可重复评估

`node --test tests/ideal-tree.test.mjs` 覆盖协议、目标规模、先修循环、真实引文、定向修复、取消、服务恢复、候选缺口、读取隔离、长文档上下文和已有资料不被写入等场景。`tests/api.test.mjs` 覆盖认证入口和无 Key 的本机结果读取。

`node --test tests/ideal-papers.test.mjs` 覆盖知识节点资料归属、版本去重、官方元数据解析、关键词检索与缓存、独立任务持久化、幂等、失败保留、修正预算、暂停/进程恢复、原始 PDF 字节保存和伪装 PDF 拒绝。`npm run test:e2e` 运行 `tests/browser/ideal-tree.mjs`，使用隔离服务器、资料库和模拟模型验证知识节点查找、PDF 导入、目标传递与刷新后打开已有笔记。

无需 Key 的可复现执行记录见 [harness 演示](../../examples/harness/README.md)。它使用真实 runner 和模拟供应商，展示中断续接与有限修复，不是模型效果评测。

运行 `node scripts/evaluate-ideal-tree.mjs <构建记录.json>` 可离线检查结构、计数、来源引文与运行指标。公开导出缺少正文时，引文检查明确记为 `not_evaluated`。报告不会把通过 JSON 校验或模型自评当作教育质量得分。

本次真实模型小目标测试暴露并用于修复的案例：用户数量约束没有转为结构上限；实践字段虽在正文提及但协议字段缺失；长文档开头无法支持后部函数说明；审查把未选候选的 404 错归到已核实来源。剩余内容审查意见会保留，不自动宣称全部达标。

当前仍需后续评估：多领域的人工标注基准、同模型与同预算的消融实验、大树的成本和质量稳定性、跨分支节点级先修及人工编辑后的增量规划。当前跨分支先修粒度是分支，节点级先修限制在本分支。稳定画像不会从阅读记录或理想树推断结果自动增长。
