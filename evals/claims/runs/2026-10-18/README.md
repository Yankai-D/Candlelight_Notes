# 条件与量词复核：首轮真实结果

本轮完成了可重放的复核及局部候选流程，但结果不足以支持默认启用。最有价值的失败是：**模型看见缺少的条件，仍可能替原句补上它，再判定“没有问题”。** 来源和引文校验无法单独解决这一点。

## 分开看执行结果与语义结果

| 案例 | 执行结果 | 初步阅读 |
| --- | --- | --- |
| shrink-observed | 诊断被拒绝，1 次调用 | 同一段两项检查；说存在反例却标无问题，还改写了原句公式。没有候选 |
| shrink-corrected | 无问题，1 次调用 | 保留正确条件与正文 |
| affine-valid | 诊断被拒绝，1 次调用 | 数学解释看来正确，但重复段落项，不满足接口契约 |
| affine-overclaim | 无问题，1 次调用 | **漏检**：悄悄假设 b 不为零；b=0 的预先固定反例仍能推翻原句 |
| sampling-overclaim | 候选就绪，2 次调用 | 只撤回“每次误差必然减半”，保留前句条件；候选看来合理 |
| sampling-valid | 无问题，1 次调用 | 保留理论标准误与实际误差的区分 |
| context-cautious | 无问题，1 次调用 | 正确保留缺资料的边界表述 |
| context-missing | 候选就绪，2 次调用 | 没按预定策略停止；候选撤回无依据保证并说明缺附录，没有凭空补定理 |

本轮以“每段一项诊断”限制编辑范围，模型却自然把同段的公式与结论分成两项，暴露了协议粒度问题。不得把被拒的内容事后修好再算成功，也不应把所有失败简单归因于模型算力。

缺附录案例需要进一步明确产品策略：来源不足时“等待补充材料”与“仅撤回过满保证”都可能合理，但应是不同操作。当前 `issue` 的非空 counterexample 字段不能表达这一区别，更不能证明反例成立。

## 下一项设计工作

1. 将段落身份与段内主张分开：每段可含多个待核对主张，逐个保留原句、前提、结论及证据关系，避免强塞进一个结论枚举。
2. 明确“原文直接支持、数学推导支持、来源相反、来源不足”的证据关系；不允许通过想象隐含条件替原句开脱。可计算的反例使用有限、独立实现的数学检查，不执行模型任意代码。
3. 将缺资料的停止分支与撤回无依据保证分支显式分开，候选仍需人工接受。先对本轮失败做离线回归，再预注册新的独立材料；不继续用这 8 例宣称泛化提升。

这次没有改日常笔记生成或覆盖用户文稿。两阶段都由同一模型负责，参考标签和本文均由 AI 协作形成；尚无独立人工复核，不能报告可靠性优势。
