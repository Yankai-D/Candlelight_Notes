# v1 / v2 真实对照：边界更明确，效果未达到启用标准

v2 的原句定位、多主张覆盖和受限算术检查已能运行，但本轮未证明整体复核效果优于 v1。新版还暴露了“适用条件”与“推导依据”混淆的问题。因此保留实验状态，不接入日常生成。

## 固定条件与实际用量

[预注册计划](../2026-10-18-v2-plan.md) 和实现提交：`15db0ea9c933cbb2f45353828a9c9c23f44ef4e1`，运行时工作区干净。模型为本机配置的 `deepseek-flash`，temperature=0，thinking disabled。四份原创数学稿各跑两版，共八个候选，每个只运行一轮，没有格式修复、截断或后验补跑。

| 协议 | 实际调用 | 输入 tokens | 输出 tokens | 执行失败 |
| --- | --- | --- | --- | --- |
| v1 | 6 | 4,070 | 1,087 | 1 |
| v2 | 5 | 5,200 | 2,722 | 1 |
| 合计 | 11 | 9,270 | 3,809 | 2 |

总上限为 16 次 / 32,768 输出 tokens。v2 少一次修订调用，输入仍增加 1,130、输出增加 1,635 tokens。丰富结构带来了实际成本，不能只展示候选更详细的部分。

## 各案例观察

| 案例 | v1 | v2 |
| --- | --- | --- |
| 矩阵漏条件 | 正确反例与局部候选 | 同样得到反例，程序核算行列式为 0，局部候选加入算例 |
| 矩阵正确稿 | 保留 | 保留 |
| 向量正确稿 | 同段重复项，被拒绝 | JSON 语法错误，被拒绝 |
| 向量漏条件 | 正确指出负缩放反向并修订 | 错误推导“乘以 ±1 不改变方向”；无出处前提使程序停止，未完成纠正 |

开发标签一致项为 v1 的 3/4、v2 的 2/4，含失败在内保留全部分母；这不是独立准确率，更不是统计显著性结论。模型输出的数学判断及本文由 AI 初步审阅，尚待独立人工复核。

三个具体发现影响后续设计：

1. **可追溯的阻断有用，但不能当成正确诊断。** v2 的错误方向推导未进入修改，能追到那个没有出处的前提；原文实际上已足够构造反例，`needs-source` 仍不是应有结果。
2. **推导依据不是遗漏的适用条件。** 范数恒等式已在来源中，原句不必重复完整证明。当前规则会把来源中独有的推导事实也判作 `qualify`，有制造冗余解释的风险；这与稳定、张弛有度的笔记目标不符。
3. **新增字段会产生新歧义。** 模型把矩阵原句的 assertion 提前改成正确说法，再给出“被反驳”的关系。原始 unit 定位仍正确，但这个自由改述字段没有提供足够收益。后续应优先精简重复改述，区分适用约束和推导证据，而非继续增添一大串审查字段。

受限计算器本轮实际核算了一例：全 1 矩阵的 `1*1-1*1=0`。检查结果明确只认证算术，来源映射与反例取值条件仍标记 unverified。离线测试可以拒绝故意错误的运算关系，不应扩大宣传为任意数学语义检查。

## 保留的证据与复现

[完整 run.json](run.json) 保存原始请求、响应、编译后的候选、失败及实际用量。[findings.json](findings.json) 绑定运行哈希并逐条引用原始字段；损坏 JSON 的发现引用原始字符串，不先改好再归档。

```sh
npm run eval:claims -- --inspect evals/claims/runs/2026-10-18-v2/run.json --out artifacts/claim-eval/2026-10-18-v2-replay
```

重放不读取 Key、不发模型请求，输出页并列显示两版、原稿、候选、逐主张路由和原始失败。旧 v1 首轮记录保留原样。演示用的手工新版夹具不是实际模型改善证据。
