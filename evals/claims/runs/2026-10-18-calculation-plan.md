# 两阶段计算含义复核：调用前计划

上一轮单项提醒没有改变真实均值窗口的判断。本轮实现可审阅的中间解释，比较完整的两阶段机制与现有 focused 基线，不把结果归因于某一句提示词。

## 输入与阶段边界

1. 提取阶段只看笔记与原句单元：没有 source 正文、页号或参考标签，保留全部笔记上下文。笔记内已有公式仍可见；提示要求忠实记录解释文字，不能用旁边正确公式替它纠错。输出分 calculation、intuition、context、unresolved，计算条目必须引用本句连续文字并写出其计算规则。
2. 程序检查完整覆盖、引文范围、条目数量，将解释绑定到笔记和来源快照。表达式只是文本，不执行代码，也不宣称已完成数学证明。
3. 比较阶段得到完整来源和已接受的提取，逐条给出来源表达式及 compatible、conflict 或 needs-source，再沿用原有逐句 verdict。必须覆盖每条规则，引文必须来自允许页；冲突不能一边记 conflict 一边 retain，缺定义或含义未明不能强行判错。提取与来源映射是否正确仍待内容审阅。
4. 每阶段最多一次实际请求，失败停止当前候选并保留已经接受的提取。没有格式重试、自动改稿或用户数据写入。

## 材料和预先判据

| 案例 | 来源 | 关注点 |
| --- | --- | --- |
| mean-observed | 已见真实 field w4 完整窗口 | b7:s2 是否真正提取“自身大小作权重”的含义，继而定位差异 |
| mean-equal-control | 已见局部正确控制 | 等系数平均保留，其他句不误伤 |
| mean-contribution-control | 已见直觉正确控制 | 贡献大小不能被错读为权重变化 |
| weighted-control | 已见原创控制 | 合法不同权重不误报 |
| center-order-mismatch | 已见原创操作顺序错误 | p1:s2 判矛盾，正确公式 p1:s1 保留 |
| center-order-control | 已见对应正确控制 | 正确顺序保留 |
| balance-metaphor | 新编纯比喻控制 | 不把等质量砝码比喻误认为另一套数值权重规则，检查提取出口 |
| undefined-transform | 新编定义缺失控制 | p1:s2 请求定义，不能凭常识发明 Q |

前六例与上次输入完全相同；后两例与协议共同设计，全部属于开发数据，不是留出集。AI 编写参考不进入任何真实请求，也不是人类独立认证。均值材料沿用 OpenIntro Statistics 第四版及其中文改编，作者 David Diez、Mine Çetinkaya-Rundel、Christopher D Barr，CC BY-SA 3.0；见 [来源署名](2026-10-18-field/README.md)。新比喻和未知变换是原创开发探针。

成功判断不能只看最终标签：若最终指出问题但第一阶段歪曲原句，仍记为解释失败。若第一阶段把原句重写成正确规则，即使格式通过也保留该漏检。检查所有正确控制的误报、来源不足的错误分支、阶段格式失败、原始响应和成本；不把失败候选算成正确，也不把诊断当成安全修订。

## 固定预算与真实执行

deepseek-flash、temperature=0、thinking disabled；每例基线一次、两阶段组最多两次，交替顺序。八例最多 24 次实际请求，每次最多 2,048 输出 tokens，总输出上限 49,152，输入另计。两阶段组有更多调用及可用总输出额度，明确报告，不声称是等计算量实验。

真实运行前提交协议、测试及本计划，保存 clean revision。只运行一次整批，观察结果后不改提示重跑本批。没有收益则保持实验状态；即使本批改善，也只能进入更大真实材料验证，不能宣传普遍准确率。

```sh
npm run eval:claims -- --calculation
npm run eval:claims -- --calculation --demo
npm run eval:claims -- --inspect <run.json> --out <新目录>
```

默认冻结计划，demo 注入离线响应，inspect 零调用重放。真实调用必须显式 `--calculation --live` 并逐一列出上述八个 `--case`。检查点保存提取完成及比较失败的状态；本轮尚无断点自动续跑功能。
