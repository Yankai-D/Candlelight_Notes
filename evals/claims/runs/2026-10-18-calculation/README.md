# 中间解释暴露了偏差，但尚未解决真实漏检

两阶段机制已经实现：先从笔记提取计算含义，再与来源逐条比较。真实试验发现，模型在第一步便把“各观测值以自身大小为权重”转成了普通算术均值，第二步按这个已经被改写的解释继续判断兼容。中间结果让失败更可定位，但本批未证明它能可靠检出目标问题，因此没有接入日常生成。

## 内容与执行分开记录

| 案例 | 基线 | 两阶段组 |
| --- | --- | --- |
| 已见真实均值错误 | 仍 retain | 提取将错误说法转成正确均值；比较想保留，但来源引文不精确，被拒 |
| 等系数正确控制 | retain | 提取增加额外 quote 字段，被拒 |
| 数值贡献正确控制 | retain | 提取增加额外 quote 字段，被拒 |
| 合法加权均值 | retain | compatible / retain |
| 操作顺序错误 | 定位解释句 | 忠实提取先除后减，再定位冲突，保留正确公式 |
| 操作顺序正确控制 | retain | compatible / retain |
| 纯平衡点比喻 | retain | intuition / context，无计算比较，retain |
| Q 定义缺失 | contradiction | needs-source，符合开发参考 |

真实均值窗口的提取引用仍含“以自身大小为权重”，expression 却为“均值 = (Σ 各观测值) / 观测个数”。这说明原句锚点正确不代表语义转换忠实；仅靠两阶段分工也未阻止它纠正自己理解的意思。第一阶段没收到来源正文，但笔记内正确公式仍可见，不能据此认定偏差唯一来自哪个输入。

该候选的来源引文把 `number\nof observations` 中换行变成了空格，因此不满足本版逐字匹配。离线核对确认仅有空白差异，不是伪造不同来源。被拒之前模型仍然返回 compatible 和 retain，所以这次阻断不能算成内容检错成功。

另外两个正确控制是 JSON 中多出了契约不允许的同级 quote 字段：一个在 calculation 与 context 条目上都有，一个只出现在 calculation 上。保留原始响应，不删掉字段后改计本次成功。这类格式容错可单独改进，但它不能解决错误解释被转成正确定义的问题。

Q 案例中，来源没有定义 Q，无法据此证明 Q(x)=x/2 为真或假。两阶段组选择请求定义，基线把缺少定义当成相反证据。这个分流符合 AI 开发参考；尚无独立审阅，不能将它写成普遍效果提升。完整逐候选证据见 [findings.json](findings.json)，人工评分保持空白。

完整 `npm run check` 通过：268 项单元/集成测试、五套浏览器流程、构建及全部离线演示。真实归档后补充四项证据回归，连同原有测试共 16 项 calculation 测试另行通过；验证提取偏差、三个失败的具体原因、缺定义分流、所有原始证据和未填人工评分。报告展示失败响应是运行后增加的只读改进，未改变协议、固定计划或真实数据。凭据扫描通过，日常服务和用户笔记未修改。

下一步的效果验证应聚焦“提取是否保留原句定义的数量关系”，不能先用正确数学常识替原句消歧，再把所得公式与正确来源比较。格式兼容与语义忠实度必须分开验收。本轮实现提供了阶段隔离、可检查中间结果及失败保留，尚不构成可信的自动数学审稿器。
