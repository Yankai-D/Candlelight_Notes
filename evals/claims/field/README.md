# 从真实生成的讲义到逐句审阅

本轮固定上一轮的 `condition-review-v1`，不继续改提示。先通过应用实际使用的生成 harness，整理已导入的 OpenIntro 均值选段，再按固定规则复核全部生成内容，包括标题、正文和列表。公开教材已参与项目样稿开发，因此这是实际资料上的开发试验，不是未见材料测试。

## 执行与边界

1. 固定公开来源、默认学习目标、基础画像、讲义模板和生成提示。生成最多两次供应商请求，生产格式修复与截断重试共享额度。
2. 对生成结果整体规划窗口。每批通常不超过八个文字单元、四个原段落，携带前后各两段作为上下文；单段最多十二个单元。上下文不参与该批目标覆盖。
3. 所有窗口通过规划后才发复核请求。超过八批或单段限制时，明确保留生成结果并报告规划失败，不截取前几段冒充全文。
4. 每批最多一次实际请求，失败保留，后续批次仍执行。每个原句只能有一个目标批次。页码和原句范围由程序恢复，不允许模型重新抄写或扩展范围。
5. 复核可检索本章提供的全部原文页；生成器填写的来源锚点保留在原始产物中，但不限制复核器寻找依据。这是明确的证据范围策略，不是假装每段已经引用了所有页。

“文字单元”由标点和公式边界划分，不等于自动识别了所有语义主张。只带邻近上下文可能遗漏远处定义；当前不验证全文覆盖原文要点、图像细节、跨章一致性或教学价值。`retain` 不是正确性证明，输出也不会写回用户笔记。

全轮最多十次请求、24,576 输出 tokens，输入另计：生成 2 × 4,096，复核至多 8 × 2,048。没有裁判 API、自动改写或生产接入。

## 独立审阅入口

```sh
npm run eval:field
npm run eval:field -- --demo
npm run eval:field -- --live --case openintro-mean --out artifacts/field-review/my-run
npm run eval:field -- --inspect artifacts/field-review/my-run/run.json --out artifacts/field-review/my-replay
npm run eval:field -- --summarize artifacts/field-review/my-run/run.json --review path/to/field-review.json --out artifacts/field-review/my-summary
```

默认只保存计划，`--demo` 为模拟响应，不读取凭据或调用模型。真实调用必须显式指定案例。重放和汇总不读取 `.env`；输出目录不得覆盖已有记录。

`review.html` 包含全文、来源、原句定位和空白判断。审阅者先判断，再展开该句的模型意见；展开时保存当时的判断，后续修改另存。同一浏览器导入旧草稿不能清除已记录的展开行为或覆盖首次判断。草稿按产物哈希隔离，支持导入、导出和刷新恢复。

人工记录使用与模型一致的四种判断；报告矛盾或遗漏条件需引用真实来源并解释原因。汇总逐句列出可能漏检、可能误报、分类分歧及模型不可用情况，避免“段落总标签对了但定位错句”被掩盖。展开前未完成的记录保持 unreviewed，不能用展开后补填的答案代替首次判断。尚未获得实际人工记录时，状态始终为 awaiting-human-review。

审阅者须声明是否为人、是否参与开发、此前是否看过模型诊断。页面文件已包含模型输出，因此隐藏展示只是减少提示影响，不能称为保密盲评；身份、能力和独立性均为自述，程序不能认证。AI 不能代填人工记录获得独立评测成绩。汇总不自动给准确率或优势结论。

`run.json` 保留生产请求、原始响应、最终正文和逐批复核；重放会重新从供应商响应验证结果、重建覆盖，不只信任保存的 successful 字段。人工模板、模型报告和 AI 初步发现分开保存。预先计划见 [本轮方案](../runs/2026-10-18-field-plan.md)。
