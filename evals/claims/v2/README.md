# 主张、前提与证据关系：v2 实验协议

v1 的真实运行暴露了段内多个主张被压成一个判断、模型擅自补前提，以及缺来源被当成反证的问题。v2 把这些信息变成可检查的数据结构，仍是独立实验组件，未接入应用生成，也不声称程序能判断任意自然语言真伪。

## 职责与边界

| 层次 | 谁负责 | 输出与限制 |
| --- | --- | --- |
| 原句定位 | 程序 | 按公式/代码外的句末标点生成单元 ID 和 UTF-16 范围，保留原文；这是定位器，不是语义分句器 |
| 主张划分 | 模型提出，程序验收覆盖 | 一段可有多项主张；每个目标单元恰好归属一项，连续且不重复；覆盖文字不等于覆盖了所有事实 |
| 前提来源 | 模型列举，程序匹配引文 | 明确笔记、周围上下文、原文或无依据；不能仅因引用存在就认为它支持前提 |
| 证据关系 | 模型提出 | direct / derived / contradicted / insufficient / context，各自有不同必填字段 |
| 数值算例 | 程序核算 | 固定运算树、精确有理数，禁止执行代码；只验证算术，不验证来源映射和取值是否满足所有假设 |
| 修改分支 | 程序 | 纠正/补条件、等待来源、保留，以及显式启用的撤回保证；模型不能选择启动撤回操作 |
| 提交 | 尚未接入 | 同快照候选预览，原稿保留；未来需要用户接受和独立语义审阅 |

`server/claim-audit.mjs` 保留最多 12 个目标文字单元、96 个总单元；超出限制报错，不遗漏难句换取通过。原有每例两次调用、每次 2,048 输出 tokens、总计 4,096 的预算不变，底层截断重试也消耗同一预算。诊断与修订之间可取消，失败后保留原稿和已完成诊断。

没有笔记或来源锚点的必要前提会使“支持”判断转入 `needs-source`。前提仅出现在来源中则转入 `qualify`，形成补条件候选；这仍需要人工确认，因为程序不知道那段引文是否真的支持该前提。明确反证可以推翻原句，即使原句缺少其他必要条件；不能把所有遗漏条件一律当作等资料的问题。

`insufficient` 默认停止。调用方显式传入 `withdrawUnsupported: true` 才允许撤回过满保证，输出标记 `withdrawal-proposed`；该类型不能冒充纠正后的知识结论。混合范围存在来源缺口时，默认先停下，不悄悄只修其他部分。单批超过三项待修订主张要求缩小范围。

修订只返回 claimId 和 after，程序按原始偏移替换，避免模型抄错公式定界符。多个修改从后向前合并；其余文字、公式、来源和修订号保留。公式仍经过现有 `reading-tree-note-v1` 编译器；会连带规范化范围外文本的修改被拒绝。任何快照或审阅结果变化都使候选失效。

## 有理数检查器

`server/claim-arithmetic.mjs` 仅支持加、减、乘、除、取负、绝对值；变量不超过 12 个，表达式不超过 64 节点、深度 8。输入为限定长度的整数/分数字符串，使用 BigInt 约分，分母非零，中间结果限制长度。计算和模型声称的 equal/different 不一致即拒绝诊断，不通过调整容差掩盖边界值。

检查结果明确保留 `sourceMapping: unverified` 和 `domainAssumptions: unverified`。把错误方程输入正确计算器仍可能得到正确的算术结果，不能因此替原文背书。当前没有自动把任意论文公式编译成经过独立确认的数学模型。

## 离线与真实对照

```sh
npm run eval:claims -- --compare
npm run eval:claims -- --compare --demo
npm run eval:claims -- --compare --live --case matrix-overclaim --out artifacts/claim-eval/my-comparison
npm run eval:claims -- --inspect artifacts/claim-eval/my-comparison/run.json --out artifacts/claim-eval/my-replay
```

原有不带 `--compare` 的 v1 运行、历史记录及检查保持原样。重放根据记录自动选择协议。两版使用同模型、来源、原稿、目标与预算；案例间轮换先后顺序，各只运行一次。比较的是整套协议，不能拆成某一句提示的独立效果。

[真实对照已归档](../runs/2026-10-18-v2/README.md)：11 次请求。原句与计算边界可追溯，但整体收益未得到证明，且发现推导依据被当作遗漏条件的问题；继续保持实验状态。

旧 8 例用于已知失败回归，`fixtures.mjs` 的新版模拟响应是手工改写的协议夹具，不能算成旧失败被新模型修好了。真实比较使用新编矩阵逆与向量归一化材料，两组各含正确和漏条件版本；参考标签与数值 oracle 均不发给模型。新材料仍由 AI 协作编写并参与开发，**不是独立留出集**。预注册见 [对照计划](../runs/2026-10-18-v2-plan.md)。
