# 条件与量词复核实验

这是从真实笔记错误推进的实验组件，尚未接入应用默认生成流程。上一轮的一句话把 `P != I` 解释成“两种更新必然不同”，而差为 `-eta*rho*(P-I)*u`；零衰减以及非零衰减下的特定参数都能反驳它。来源条件已进入实际请求，因此本轮验证生成之后的复核能力。

## 执行契约

`server/claim-review.mjs` 接收不可变快照：资料和章节身份、修订号、学习目标、目标段落、上下文段落、完整引用页。不静默截断，不读取私人资料库，不修改应用持久化数据。

1. **诊断**：每个目标段落恰好返回一项判断，附原句、原文连续引文和页码。`issue` 必须具体描述矛盾或反例；`needs-context` 必须说明缺少什么，阻止后续修订；`no-issue-found` 只表示本次未发现问题。
2. **修订候选**：最多三项诊断，精确替换各自的 claim。`before` 必须与原句一致并在段落中唯一，禁止修改其他段落或来源。复用正文、小纸条和导出的内容编译器验证数学格式；会连带规范化周围文字的候选也被拒绝。
3. **预览**：复核与候选绑定同一个快照及哈希，来源、目标、身份、修订号或任一上下文变化都使旧候选失效。原稿与候选并存，不写入笔记。哈希用于一致性检查，不是签名或可信语义证明。
4. **预算**：每例至多两次实际模型请求，每次最多 2,048 输出 tokens，总计最多 4,096；包括底层截断重试。格式错误不继续反复修复；诊断已消耗两次请求时不能再调用修订。每例超时 180 秒。

模型只能提出判断。程序验证引文存在、编辑范围和渲染格式，不能证明反例正确、引文支持判断或修改没有语义副作用。诊断与修订使用同一个模型，错误可能相关。任何评估结果均须把这两层分开。

## 复现

```sh
npm run eval:claims
npm run eval:claims -- --demo
npm run eval:claims -- --live --case shrink-observed --out artifacts/claim-eval/my-run
npm run eval:claims -- --inspect artifacts/claim-eval/my-run/run.json --out artifacts/claim-eval/my-replay
```

第一条只冻结计划，第二条注入模拟响应。真实运行必须显式列出每一个 `--case`，从本机 `.env` 读取模型配置；不输出 Key，也不在记录中保存认证头。已有输出目录拒绝覆盖。每个阶段保存 checkpoint，原始请求、响应、失败和用量保留在 `run.json`，`review.html` 展示原稿、候选、精确替换范围、来源和参考判断。`--inspect` 完全离线，重建时核对哈希、实际请求和候选编辑。

8 个开发探针分成四组：真实收缩更新错误及局部修正稿；仿射映射的有效全称结论与漏条件句；标准误与单次误差；缺少附录时的谨慎表述与无依据保证。预期是 3 个错误、4 个正确对照、1 个缺上下文。参考标签、数值反例和模拟答案均不进入真实模型请求。

这些参考由 AI 协作编写，材料也已用于开发；没有独立人工标注或未见测试集。与标签一致只能记作“开发参考一致”，不能报告成真实准确率。静态数值测试验证预先定义的反例，不执行任意模型生成代码、不自动认证模型给出的反例。

本模块的离线演示已纳入 `npm run check`；实际运行仍与默认验收分开。预注册见 [首轮计划](runs/2026-10-18-plan.md)。

[首轮真实记录](runs/2026-10-18/README.md) 已归档：8 例、10 次请求，包含重复诊断被拒、隐含条件漏检及缺来源策略分歧。结果不足以支持默认启用，完整失败和候选均可离线重放。

后续的 [v2 主张级协议](v2/README.md) 把段内主张、前提出处、相反证据和来源缺口分开，加入原句编号及受限有理数核算。旧协议和旧记录原样保留；`--compare` 进入两版对照，缺来源时的撤回保证是单独的显式操作。

后续进展：简化协议的 [focused 对照](runs/2026-10-18-focused/README.md) 减少了这批开发探针的格式失败，但 [实际教材讲义](runs/2026-10-18-field/README.md) 仍出现文字与公式含义不一致的漏检。`--meaning` 的 [单项后缀实验](runs/2026-10-18-meaning-plan.md) 保留真实失败上下文，加入正确表述和跨概念控制，逐句检查收益与误报；没有默认启用生产复核。
