# 2026-10-30 完整讲义小样本 / Whole-handout pilot

本轮真实调用 `deepseek-flash`，比较冻结的 0.1.40 和 0.1.41。输入为项目原创的虚构工厂概率课程：四份材料、十一段来源，主题是条件概率、基率变化和损失阈值。画像、目标和模板相同，顺序随机后为旧版在先。两版均规划三章，各调用十四次后触及实验上限；产品没有增加恢复次数限制。

This live pilot used `deepseek-flash` with frozen 0.1.40 and 0.1.41 runtimes. Inputs were four authored fictional-factory materials containing eleven source passages, covering conditional probability, changing base rates and loss thresholds. Profile, goal and template were shared. Randomized execution order put the older version first. Both planned three chapters and reached the experimental limit after fourteen calls each; no product recovery quota was added.

这不是完整交付成本对照：两版停在不同阶段，缓存与服务速度也不受控制。不能把旧版较少的总用量解释为质量更高，也不能声称新版更省或更好。停止是独立评测上限造成的；没有测试解除该上限后各自多久完成。无单价假设，因此不折算人民币。

This is not a completed-delivery cost comparison: the arms stopped at different stages, and cache behaviour and service speed were uncontrolled. Lower total usage does not establish higher quality, and no advantage is claimed for the newer version. The independent evaluation boundary caused the stops; completion time without that boundary was not measured. No currency cost is inferred without pricing assumptions.

已定位三类开销。两版的规划都因遗漏全局要求的章节标注重写了一次。正文存在三处“概念/方法”角色缺标，其中新版的恢复模型在两次返回中明确认定正文已有内容、只补标签。新版第二章还出现属性名开头引号缺失的 JSON 错误；恢复模型作出了不精确的转义诊断，并选择整章重新生成。这个一般性语法恢复问题仍未修复，不能把新增评测或标签修复说成已经解决全部 token 开销。

Three sources of overhead were identified. Both outlines were rewritten once for missing section annotations of global requirements. Three prose outputs lacked concept/method role annotations; two recovery responses explicitly found the content already present and only added labels. The newer version also omitted an opening quote on a JSON property name. Its recovery model gave an imprecise escaping diagnosis and regenerated the chapter. This general syntax-recovery issue remains unresolved; neither the new evaluation nor the annotation fix solves all token overhead.

本轮修复仅进入项目源码，未改被冻结的对照版本或已安装应用。用途标签不足现在触发实际正文审查，不再作为必须修复的结构断言；不存在的单元编号仍拒绝。三处真实失败保留为开发回放，并用完整三章离线流程验证“已有内容被接受时，不重写、不补标签”。这证明编排行为，不证明真实审查模型必然判断正确。另修复否定目标中的任务词误判；预检时“不要额外出试卷”曾关闭讲义整合，正式对照因此统一采用“交付物仅为讲义”。

Fixes were applied only to project source, leaving the frozen comparison versions and installed application unchanged. Incomplete role annotations now trigger actual prose review instead of a structural repair requirement; nonexistent unit identifiers still fail. Three observed failures are retained as development replays, and a full three-chapter simulation verifies acceptance without rewriting or annotation repair when prose is sufficient. This establishes orchestration behaviour, not live reviewer accuracy. Negated task verbs were also fixed: preflight found that “do not additionally create an exam” could disable lecture synthesis, so both live arms used the equivalent positive instruction “the deliverable is only the handout.”

assistant 审读发现：旧版第二章把 \(s\pi=0.009\) 称为“期望人数”，量纲错误，虽然后续比例计算正确；新版首章的“判断一个比例回答哪个问题，只看分母”过于绝对，分子也决定事件。两版都有重复标题和可精简的复述。已完成内容不足以判断全篇的结构或独立学习效果。此次审阅看过版本映射，不是盲评，也不代替用户或独立教师验收。

Assistant review found that the older version called \(s\pi=0.009\) an “expected count”, a units error despite correct subsequent ratio calculations. The newer first chapter overstated that the denominator alone determines what a proportion answers; the numerator also defines the event. Both repeated titles and some explanations. Available prose cannot establish whole-course organization or self-study effectiveness. The reviewer saw the version mapping, so this was not a blind review or independent learner/teacher acceptance.

This offline result does not change this pilot's historical usage or failure outcome. Subsequent live validation is recorded separately.
