# 主产品场景：调用前约定

本轮回到论文笔记、课件整理和小纸条三个使用场景。数学自动复核实验暂时冻结：保留历史失败、离线重放与测试，不继续增加协议，也不接入默认产品生成。

## 固定比较

| 场景 | 输入 | 任务 |
| --- | --- | --- |
| 论文长文 | ResNet §3.1，第 3 页及脚注 2 | 把残差的局部数学关系接回退化问题，保持连贯、张弛有度 |
| 课件整理 | 已导入 OpenIntro 分类数据课件的 5 页文字 | 按知识依赖组织单元，解释图表类型、群体内比例与分母 |
| 小纸条 | 同一 ResNet 选段、固定已有中文笔记及选区 | 回答“换个写法为何有帮助、F=0 是否一定更好”，避免重讲整章 |

固定本科理科基础画像；每场景比较 `direct` 与当前生产 `harness`，各一次，共 6 份候选。模板固定为现有长文／讲义模板，不改生产提示词，不启用条件、含义或两阶段数学复核。两种方法获得相同证据、目标、画像，小纸条还获得相同已有笔记、选区、插入位置和追问。验收要点不发送给模型。

每候选最多 2 次实际调用、每次最多 4096 输出 token、累计最多 8192，最多 12 次调用及 49152 输出 token；输入另计。结构修复和截断续接都占同一额度。直接调用没有生产格式修复循环，保留这一流程差异与实际用量，不声称纯提示词单变量对照。一次运行后停止，不根据表现挑选候选、删除失败或反复调参。

ResNet 文字来自用户已导入的原 PDF，按页面核对选段并保留脚注；记录全文文件哈希。OpenIntro 原样复用已有授权课件文字并保留署名、许可与页码映射。图像不作为模型输入。ResNet 不冒充 CC 许可材料；公开发布包含其正文的评测产物前需另核对再分发权利。

## 如何判断

复用既有六维评分：事实与条件、实质覆盖、推理与主线、组织与文风、学习目标、铺垫深度。场景专属验收要点见 `product-scenarios.mjs`，小纸条只评新增内容，不以整章覆盖率扣分。重大错误单列，不能被文风分数抵消。

审阅页隐藏方法标签；必须保留原文和已有笔记，便于核对。人工表单初始为空，AI 初步观察不能填成独立人工评分。先由未参与调教的人审阅，再揭示方法标签；单人评分不宣称评审共识。没有独立审阅时只报告交付、格式、用量和待判断事项。

本轮是公开开发诊断。论文与小纸条共享来源，只有两组独立来源，不足以证明泛化、跨画像稳定性、全文衔接、模板路由或学习成效。即使 6 份都结构通过，也不报告 harness 已有质量优势。

## 执行与重放

```sh
npm run eval:notes -- --suite product-scenarios --demo
npm run eval:notes -- --suite product-scenarios --live --case resnet-residual --case openintro-categorical --case resnet-inline
npm run eval:notes -- --inspect <private-run.json> --out <新的审阅目录>
```

沿用 `eval:notes` 的计划哈希、预算、检查点、失败分母、原始响应和审阅页，不新建一套评测服务。真实调用前先通过相关离线测试；实际代码版本和工作区状态写入产物。独立人工审阅后再决定哪一个具体问题值得修，避免用更多机制掩盖尚未验证的学习体验。
