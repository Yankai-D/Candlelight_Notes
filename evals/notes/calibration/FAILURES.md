# 失败登记与改进策略

本表是开发校准的分类，不是已经测得的线上错误频率。每条先看来源与上下文，再决定是否需要改提示词。修改建议是待真实对照验证的假设。

| 校准用例 / 类型 | 文本上的判断依据 | 优先检查的位置 | 改进假设与复测关注点 |
| --- | --- | --- | --- |
| `math-purpose` / 推导未回到问题 | 有正确差值和系数，却未说明它们如何回答参数衰减问题 | 长文组织约束、章节前后文 | 在关键转折交代计算目的并解释结果；复测是否造成每段机械添加导读与小结 |
| `variance-conditions` / 丢失成立条件 | 把独立、共同有限方差下的关系扩张到任意观测 | 来源抽取与分段是否保留条件；生成中的实质覆盖 | 让条件随公式进入同一上下文；复测相关样本和条件相邻但跨页的材料，不能只检查“独立”一词 |
| `profile-voice` / 画像改变文风 | 画像只改变熟悉程度，却切换为另一种叙述口吻 | 模板与画像职责、模板快照是否固定 | 文风约束保持固定，画像只影响铺垫深度；比较两份笔记的事实、术语和叙述视角 |
| `known-prerequisites` / 重复已知铺垫 | 重新讲完整组已知定义，不能帮助继续当前推理 | 稳定画像上下文、讲解深度约束 | 只补实际推理所缺前提；复测基础画像是否因此失去必要说明，不能简单施加字数上限 |
| `paper-note` / 纸条未回答追问 | 新纸条重复现有正文，没有回答明确问题或完成指定算例 | 选区、锚点、当前正文和用户诉求是否传全 | 强调局部增量解释；复测不应移动或重写周围正文，也不应臆造实验数字 |
| `unsupported-claim` / 补充变成虚假保证 | 真实引文不支持新增的收敛／效果保证，甚至与其相反 | 来源归属约束与语义审阅 | 区分原文结论、辅助推导与未获支持的猜测；检验数值、条件和证据，不能把引文字符串匹配称为事实验证 |
| `goal-focus` / 内容未回应目标 | 指标都算对，却没说明它们与用户关注的错误代价有何关系 | 目标是否完整传入、解释重点如何安排 | 围绕目标解释已有事实；复测默认“看懂这篇文章”不会被扩张成作业或学习计划 |
| `lecture-substance` / 提纲替代讲义 | 标题下面只有“复习、注意”等提示，没有计算、口径与单位 | 讲义模板的段落职责与覆盖约束 | 将提纲展开为可独立回查的知识单元；复测不会把长文模板也拆成同一套栏目 |

前六类并不都必然是重大错误。范围、严重性和用户目标决定影响。例如重复铺垫通常影响讲解质量；错误公式条件、虚假保证、核心论证缺失则应单独登记重大问题，不能由流畅文风抵消。

## 一条真实失败需要保存什么

复制下面的记录结构进入对应运行的审阅附件。不要把真实 Key 或认证头加入记录。

```json
{
  "runId": "对应真实运行",
  "candidateId": "对应候选",
  "artifactHash": "绑定输出与来源的指纹",
  "failureCode": "missing-assumptions",
  "severity": "major",
  "noteQuote": "真实笔记中的短引文",
  "sourceEvidence": [{ "page": 1, "quote": "来源中的条件或关系" }],
  "reason": "说明当前文本为何不能满足任务",
  "suspectedLayer": "context-or-generation",
  "proposedChange": "待验证的最小修改",
  "counterRisk": "这项修改可能损伤什么",
  "verification": "哪些现有案例和新增案例必须复测"
}
```

来源条件根本没有被抽取出来时，应先修抽取或向用户显示证据缺口。格式问题进入机械回归；语义问题进入带证据的人工审阅。相同症状可能有不同原因，分类只是定位入口。

## 本轮机械回归登记

| 场景 | 期望行为 | 生产路径 |
| --- | --- | --- |
| 非法 JSON / 未闭合数学定界符 | 拒绝候选，不修改正文 | `validateResult` + 共用公式编译器 |
| 页码超出本章 / 修改其他章段落 | 拒绝越界候选 | `validateResult` |
| 真实页码配伪造引文 | 清除精确引文，保留合法页码回退 | `validateResult` |
| 等待期间修订号变化 | 不覆盖用户新编辑 | `applyResult` |
| 小纸条锚点失效 | 在调用模型之前拒绝 | `buildMessages` |
| 合法纸条 | 只新增纸条，前后正文原样保留 | `validateResult` → `applyResult` |
| 一次格式失败后成功 | 总计两次模拟调用，接受完整结果 | `runModel` |
| 连续格式失败 | 一次修复后结束，未交付候选 | `runModel` |
| 连续输出截断 | 一次更高额度重试后结束，不进入格式修复循环 | `runModel` → 提供方适配器 |

为避免错误测试“碰巧通过”，回归还检查错误类别、输入不变及实际调用次数。允许通过的纸条和修复成功场景作为正向对照。
