# 评测校准包与失败回归集

这轮建立两个互补的验收层：**人如何判断笔记的内容质量；程序如何守住提交与修复边界。** 使用现有生产 harness、笔记协议和公式渲染，不重新实现一套评测用的编辑器。没有调用真实模型，也没有修改产品提示词来迎合这些样例。

## 本轮交付

- 8 个局部教学任务、16 份正反对照，覆盖现有六个评分维度；另有一份基础画像参考段落，用于跨画像比较。
- 每个参考判断都有笔记原句、来源原句、分数区间、问题归类和修订方向；重大错误单独登记。
- 11 项机械回归调用生产校验器、文档提交逻辑与模型适配器，包含允许通过的对照。
- 独立 HTML 工作册：逐单元阅读、公式显示、记录判断、展开参考、草稿恢复、JSON 导入导出。
- 带版本及材料哈希的冻结记录、分歧汇总、命令行入口、自动测试与 CI 接入。

所有来源和样稿均为本项目原创开发材料，AI 协作编写；不是实际论文、线上模型输出或独立专家评分。当前参考判断状态为 `awaiting-independent-review`。把它们用于统一审阅尺度，仍需要人在真实资料上验证这一尺度。完整单章生成质量、全文衔接、模板路由、检索和理想树教学质量不在此校准包范围内。

## 使用

```sh
npm run eval:calibrate
```

命令不读取 `.env`、私人资料库或模型配置，不接受 `--live`。全部模型响应来自写死的模拟供应商。输出默认放在新的 `artifacts/calibration/<时间>/`，也可用 `--out <新目录>`；拒绝覆盖已有目录。

| 文件 | 内容 |
| --- | --- |
| `calibration.html` | 可直接用浏览器打开的离线工作册，不加载网络资源 |
| `corpus.json` | 原创来源、任务、完整模板及画像快照、候选与参考判断；含材料哈希 |
| `packet.json` | 工作册任务与经生产编译器处理的内容节点 |
| `answer-key.json` | 开发参考判断；不作为专家共识或真实模型结果 |
| `review.template.json` | 空白审阅结构 |
| `regressions.json` | 11 项执行回归结果与语义能力边界 |
| `manifest.json` | 版本、Git 状态、材料指纹和零真实模型调用声明 |

建议先选一个单元，阅读来源、学习目标和画像，再分别填两份笔记的本项分数、是否需要修改、重大问题、主要问题和正文依据。分数只针对本单元注明的维度，不能冒充整份笔记的完整六维评分。来源遗漏可引用邻近正文，并在理由中指出缺少什么。

“画像改变文风”单元同时给出基础画像参考段落；两份候选均面向熟悉画像。“小纸条”单元给出现有正文及明确追问，判断新增解释是否有增量价值。

展开参考不会自动填写你的答案；展开记录会随 JSON 保存。参考已在页面中，不能称为保密盲评。浏览器草稿按材料哈希隔离；不支持本地存储时会提示下载。导入其他材料、错误版本、重复记录或字段类型错误的文件不会覆盖当前草稿。

填写后下载 `calibration-review.json`，执行：

```sh
npm run eval:calibrate -- --summarize artifacts/calibration/<运行目录> --review <calibration-review.json的路径>
```

汇总核对版本、材料哈希、ID、完整字段及真实正文引文。缺项得到 `awaiting-calibration-review` 和非零退出码；完整记录得到 `calibration-reviewed`，按项列出与参考的分歧，不计算模型胜率、综合质量分或审阅者“正确率”。每次汇总写入新文件，保留讨论前的判断。

对齐参考不代表审阅正确；分歧也不自动意味着审阅者错误。建议两位审阅者各自保存首次记录，再讨论：原文能否支持判断、分数尺度是否含混、样例是否同时引入了其他问题。讨论后改规则须升级版本并重新生成材料包。只有一人审阅时如实记录人数。

## 两层检查的明确分工

16 份内容候选都能通过生产结构与公式校验，其中 8 份按开发参考需要修改。回归测试刻意保留这一事实：格式合法并不能保证推导与背景关联、文风稳定、目标落实或引文支持主张。没有用篇幅、标题数量或关键词替代语义判断。

机械回归检查以下实际行为：非法 JSON、越界页码、损坏公式、越界段落、过期修订与失效锚点必须阻止提交；无法证实的引文去除精确定位但保留合法页码；合法纸条只插入原段落之后；格式错误最多修正一次，连续截断不会无限进入修复循环。它们既检查预期结果，也检查错误类别、调用次数和原文不被修改。

参考判断不会进入 `buildMessages` 的请求。材料和模板快照参与哈希；模板代码改变时旧工作册的汇总会要求重新生成。旧工作册与导出的原始 JSON 仍可查看，不自动重解释历史评分。

## 如何用于下一轮提示词工程

1. 先用本包校准审阅者，保留分歧。真实效果实验仍使用现有 [A/B 评测工具](../README.md)，不能拿原创正反例充当模型输出。
2. 经明确授权后，从少量真实生成结果中登记问题：运行 ID、原文依据、输出引文、失败类型、影响和调用成本。类型定义见 [失败登记与改进策略](FAILURES.md)。
3. 区分来源抽取、上下文选择、生成表达、校验和提交的原因，只改与证据对应的层；不要把所有问题都补成一条 system prompt。
4. 固定模型、材料、目标和预算规则重跑对照，保留失败候选。既看目标问题是否减少，也看是否损伤另一种模板、画像或纸条的表现。
5. 真实结果用于调教后标记为开发案例；另行冻结未用于调教的材料。当前校准包全部属于开发集，不声称泛化优势。

`npm run check` 自动运行本包，正式浏览器验收还检查草稿恢复、导入导出、公式、纸条和窄屏布局。自动通过意味着工具和执行边界符合这些用例；人工校准尚未由独立审阅者完成。
